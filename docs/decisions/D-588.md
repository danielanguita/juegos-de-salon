## D-588 · A script that opens every game's page runs only for the games a PR reaches
**Date:** 2026-11-19 · **Status:** current · **Relation:** extends D-329, D-391 and D-516 (test only what can break) · **Topics:** tests, structure
**Context:** `landing-fold.mjs` measures every game's landing, every Uno al día cover and La Copa's day covers (~4 min per phone width). The graph read only the strings it names (`'panel'`, `'labs'`, `'cup'`, two of them to leave out), so it ran whole for a change to the lab's index and never for a change to a game's own cover. On 2026-11-18, [#1624](https://github.com/ellokojavi/juegos-de-salon/pull/1624) (Croc's lab card only) went red twice on Generala's day cover, which it did not touch, while Generala's own PRs never ran the check.
**Decision:** (1) `ONLY` in `tools/e2e/ci.mjs` declares the scripts that open a known set of pages in a loop and take `--only <ids>`: each id with the routes it opens (today `landing-fold.mjs`, from the same sources it reads: PATHS' `intro`, Uno al día's games, La Copa). Those routes are the script's pages in the graph. (2) When each changed site file is one game's own (it reaches the pages of a single id), the job runs as `landing-fold.mjs:320@generala`, which `ci.mjs` passes as `--part 320 --only generala`. (3) It runs whole when a changed file is shared (it reaches two ids or more: `base.css`, `cup/style.css`, `cup/game.js`, a Cup game's engine), when it reaches every id, when the script or a module it imports changed (`paths.mjs`, `uno-al-dia.js`), when the graph cannot narrow the change, and on `main` without a PR. A change that reaches no landing (the lab's index) does not run it.
**Why:** a landing that loads nothing the PR changed cannot move its button; the graph already says which pages load what (D-391), so the script's pages are derived from its own list of landings, not from the strings it happens to name.
**Consequences:** a one-game PR runs landing-fold for that game (15 s instead of ~4 min per width), and every game PR now checks its own cover, which it never did. Shared changes and `main` keep the whole run. A narrowed job is not measured into `durations.json`; `groups` estimates it as its share of the whole. `tools/e2e/only.test.mjs` pins the cases and fails if `landing-fold.mjs` measures a source `landingRoutes()` does not know.
