## D-576 · A double tap counts once, and its e2e script proves it
**Date:** 2026-11-17 · **Status:** current · **Relation:** — · **Topics:** identity, agents
**Context:** On Blackjack's felt, «Siguiente ronda» faded the table for 320 ms before moving on; a second tap in that time skipped the wait and moved the round at once, then again, leaving the table without cards (fixed by the contributor's PR #1543). The lab fast lane runs no agents, the usability agent reads screens and does not tap twice, and the e2e script tapped once and waited: nothing could see it.
**Decision:** A button whose action waits on an animation, a fade or a deal takes the first tap only (C-14). The game's e2e script double-taps each such button with `doubleTap()` (`tools/e2e/double-tap.mjs`) and checks the screen after; the canons' checklist and the usability agent ask for it.
**Why:** A double tap is the most common way a player meets a race, and it is cheap to reproduce in a script; the check written for Blackjack fails on the code before #1543 and passes after.
**Consequences:** Rule `double-tap` in `docs/rules.json`, check and judged: the scripts that double-tap are the check, the session building the game and the usability agent judge which buttons need one. Blackjack's script is the first.
