## D-591 · A scheduled launch runs only in Claude's cloud, never on the Mac, and checks itself
**Date:** 2026-11-20 · **Status:** current · **Relation:** amends D-529 (who dispatches the `launch` workflow) · **Topics:** structure, marketing
**Context:** Dominorama and Memorice were to launch at 18:08 Pacific on 2026-11-19 through a scheduled task of the desktop app on the Mac mini. The task started on time, but its first command waited for a permission approval nobody was there to give; the launch went out by hand 46 minutes late, and nothing warned anyone. The owner: a scheduled task that does not run is very serious, and no launch may depend on the Mac mini or anything outside Claude's own suite.
**Decision:** A launch at a set time is dispatched only by a **Claude Code cloud scheduled task** (claude.ai/code → Routines), one-time, created from a cloud session or `/schedule` inside the repo (tools/jobs/README.md), following `tools/jobs/prompts/launch.md`: it runs the `launch` workflow, then reads Firebase back and checks the pages, and sends the owner a push notification either way. Never a desktop-app scheduled task, a launchd job or anything else on the Mac. Every launch gets a second one-time cloud task about 10 minutes later, the alarm, that only checks the same values and notifies the owner at once if they are not set. The session that schedules it confirms both tasks exist on claude.ai/code → Routines before telling the owner it is scheduled.
**Why:** a cloud task runs unattended with no permission prompts and no machine of the owner's to be asleep, closed or waiting; a launch that checks itself and a separate alarm turn a silent failure into a message within minutes.
**Consequences:** `tools/jobs/prompts/launch.md` is the prompt for both tasks (its parameters filled in per launch). D-529's workflow and `launch.mjs` stay as they are (harmless if early or twice); only who dispatches them changes.
