## D-610 · A merge of main reruns the PR's own scope, not main's
**Date:** 2026-11-23 · **Status:** current · **Relation:** amends D-392 · **Topics:** tests
**Context:** #1802 changed the profile and its test. Its own `end-to-end` run (the profile script) passed in
about 8 minutes; then the branch took a merge of `main`, and `since-passed.mjs` counted the 19 files that
merge brought (duels, the player, the home page) as the push's. The run went to the home page's level, 18
batches of scripts the PR never touched, and the owner waited half an hour for a one-line change.
**Decision:** when the files changed since the PR last passed include any the PR itself does not change
(they came from `main`), the push tests the PR's own files again, against the new `main`, as its first push
did, and not main's. A push of the PR's own files still tests only those (D-392).
**Why:** main's files were tested on main. What a merge can break is the PR against the new main, and the
PR's own scope tests exactly that; main's scripts against the PR's change are reached by the PR's files.
**Consequences:** a merge of `main` costs the PR's scope, never more. Because it is the PR's whole scope,
the run may leave the tree's mark like a first push (D-308), and `publish.yml` keeps its net (D-496).
`filesToTest` in `tools/e2e/since-passed.mjs` holds the rule; `since-passed.test.mjs` tests it; the log
says when it happened.
