## D-578 · The end-to-end tests read a snapshot of the flags, and a new test no longer makes the README stale
**Date:** 2026-11-17 · **Status:** current · **Relation:** extends D-498 (flags flipped from /labs/ with no PR), D-518 (CI failures become mechanisms) · **Topics:** agents
**Context:** On 2026-11-17 the owner launched install-invite from /labs/ and five open PRs went red at once (and the tester tab, three): the tests read the flags live from Firebase, so a flip with no PR changed what every PR was tested against. The same day two PRs failed only because they added a test file, which made the README's test list stale and asked for a seal.
**Decision:** `launch()` in `tools/e2e/cdp.mjs` answers every request for `flags.json` with `tools/e2e/flags-snapshot.json`; a script that needs another state sets it with `browser.flags({...})`. The processes round refreshes the snapshot in its PR when Firebase differs (`flags-snapshot.mjs check | refresh`). The README's unit-test block is one loop instead of one line per test, and a test or e2e script that appears or goes is a warning, not an error that asks for a seal.
**Why:** A launch reaches the tests through one PR, where what it breaks is fixed once, instead of through every open PR at the same time. Adding a test should never fail the PR that adds it.
**Consequences:** The tests see the snapshot, not today's production: the round keeps it fresh. A script that relied on a launched state must keep working with the snapshot or set its flags.
