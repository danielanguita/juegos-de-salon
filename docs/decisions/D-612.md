## D-612 · A merge of main reruns only what both the PR and main reach
**Date:** 2026-11-23 · **Status:** current · **Relation:** amends D-610 · **Topics:** tests
**Context:** with several PRs open, the merge queue (D-586) brings them up to date one at a time and each
update reruns `end-to-end`; the 20 runners sat full (20 jobs running, 33 queued on 2026-11-23) and the last
PR in line waited up to an hour. D-610 made a merge of `main` rerun the PR's own scope, but 46 of the 97 PRs
of 2026-11-21..23 reach the home page or core files, so their merges still ran all 18 batches. Main-merge
pushes were 85 of 268 runs and 38 % of the end-to-end runner minutes.
**Decision:** a push that brings files only `main` changed runs the jobs the PR's own files reach **and**
the files the push brought reach, plus every job the push's changes to the PR's own files reach (a fix, a
conflict resolved). `since-passed.mjs --brought` writes what the push brought; `ci.mjs --meet` keeps the
meeting (`meetJobs`). A push of the PR's own files still tests only those (D-392).
**Why:** a script only the PR reaches loads nothing `main` changed since the PR last passed, so under the
same page graph every scope already trusts (D-329) it gives the result it gave then; a script only `main`
reaches passed on `main`. What both reach is what a merge can break. Anything the graph cannot narrow on
either side (a shared e2e helper, a file fetched at run time) still reaches every script, so the meeting is
then the PR's whole scope, as before.
**Consequences:** replayed over the 89 main merges of 2026-11-21..23, 752 batches instead of 1092 and 5,352
script minutes instead of 8,118. A met run keeps `since`, so it leaves no tree mark (D-308): `publish.yml`
then runs smoke plus what `main` gained since the PR head passed (D-496), one batch when the PR was up to date.
`since-passed.test.mjs` tests `filesToTest` and `meetJobs`.
