## D-600 · A player changes their own name, with their PIN
**Date:** 2026-11-21 · **Status:** current · **Relation:** amends D-513 · **Topics:** rankings
**Context:** Until now a name was for life: the profile's ⚙️ said «Para cambiarlo, escríbenos» and only the owner renamed players, with `tools/firebase/rename-player.mjs` (D-513). The owner asked for the profile's account controls to change the name and the PIN and to sign out.
**Decision:** The profile's 👤 Tu cuenta (lab flag `profile`) changes the name with the player's PIN, as changing the PIN asks for the current one (D-464). `jugador.js` `renombrar(pin, nombre)` proves the PIN (`jugadorIntentos`) and writes, in one update, `jugadores/<jid>/n`, the new search key in `jugadorNombres` and the old key's removal, and a mark `jugadorRenombres/<jid>`. The rules allow those three writes only from a phone seated as the player whose attempt in the last minute holds its key. The table rows, which must carry the player's name, are not rewritten by the phone: the hourly job (`tools/jobs/uad-hourly.sh` → `rename-player.mjs --pending --apply`) carries the new name to every row that still has another one and clears the mark (a player renamed again meanwhile keeps it for the next hour). A new name goes through the same offensive-name list as a sign-up (`name-guard`).
**Why:** a phone cannot rewrite its rows under the rows' rules (a row only improves), and loosening them would let a phone touch its scores; one admin pass an hour is enough, and the old name in a table for under an hour is harmless. The PIN keeps a borrowed phone from renaming its owner.
**Consequences:** Names are still not unique: the new name is found with the same PIN, like any other. The owner's rename tool stays for offensive names. The test store (`jugador-local.js`) mirrors the new rules, and `firebase/player-rename.test.mjs` checks both.
