## D-574 · Each heartbeat relay starts the next one itself
**Date:** 2026-11-17 · **Status:** current · **Relation:** amends D-564 · **Topics:** pwa
**Context:** Each relay of `notifications.yml` lasts 5h40m and the hourly cron was meant to queue the next, but GitHub skips most of those runs: relays started 8 to 9 hours apart, leaving about 3 hours a cycle with no notifications, no Uno al día rebuild and, since D-569, no feedback upload.
**Decision:** At the end of its loop, a relay runs `gh workflow run notifications.yml -f relay=true` (the workflow token, `actions: write`); the new run queues behind it in the concurrency group and starts as soon as it ends. A manual run with `relay` checked starts a relay too. The hourly cron stays only as the backup.
**Why:** The heartbeat becomes continuous without any machine, which lets the Mac mini's chores move to it with no loss (D-569).
**Consequences:** If a hand-off is lost, the cron or a manual `relay` run restarts the chain; heartbeat-watch.mjs (D-565) still reports gaps.
