## D-567 · Lab features get an on/off switch in the «T» tab; launched ones lose it
**Date:** 2026-11-16 · **Status:** amended by D-592 · **Relation:** completes D-551, D-498 · **Topics:** structure
**Context:** Testing the comments balloon (D-566) needed a way back after closing it, so the owner asked for a control in the tester tab, and then made it a general rule (2026-11-16): "Features que salen del apps ya no necesitan toggles en el tab de testing T, mientras que features que entran a labs deben tener un toggle en el tab para poder ser activado o desactivado y así poder probarlo más fácilmente."
**Decision:**
- **By itself, for every lab flag:** `flag('<id>')` records each flag the page asks while it is 'lab' and the visitor holds the key (`labHere`); the tester tab lists them with an on/off switch (`labSwitches`). Off turns the feature off on that phone only (`juegos-de-salon:flags-off`) and reloads the page; on brings it back. Not the tab's own flag (`tester-ribbon`) nor `lab-ready`.
- **Launched, gone:** a flag set to 'all' is not recorded, so its switch disappears and the phone's "off" no longer counts. A screen's own testing control for a lab feature (such as «Mostrar de nuevo» for the balloon) shows only while its flag is in the lab, and goes with the gate.
**Why:** Trying a feature means seeing the page with and without it, without asking the owner to flip /labs/ for everyone in the lab; and once it reached everyone, a switch would only let a tester see something players do not.
**Consequences:** A new lab feature needs no work to get its switch: asking `flag()` is enough. Canon C-12 says so; `flags.test.mjs` and `tools/e2e/cup/talk.mjs` check it.
