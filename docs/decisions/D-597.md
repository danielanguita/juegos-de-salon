## D-597 · Agents that must not touch code are stopped by a hook, and PRs flag documentation drift
**Date:** 2026-11-20 · **Status:** current · **Relation:** — · **Topics:** agents
**Context:** An outside review of the agents found that "it does not touch app code" was only a line in the documentation, ideas and retention prompts: nothing stopped them, so a misread prompt could edit a game. And the documentation agent's own check (`document.mjs check`) ran only in its daily round or when a session remembered it, so drift on a PR was found a day late.
**Decision:** A PreToolUse hook in `.claude/settings.json`, `tools/agents/scope-guard.mjs`, reads the `agent_type` Claude Code passes for a subagent's edit and blocks Edit/Write outside its scope (`SCOPES`: documentation edits docs, changelog, README, CLAUDE.md, the guides and the app's introduction messages; ideas and retention edit docs and changelog only). The `tests` workflow runs `document.mjs check --from` on every PR and turns each ✗ into a warning on the PR.
**Why:** A boundary that matters is enforced, not requested. The check is deterministic, so it runs where the change is, and the agent keeps the part that needs judgment: rewriting the prose.
**Consequences:** The hook is in settings, not in each agent's frontmatter: frontmatter hooks do not run in headless (-p) or untrusted sessions, where the rounds run. A new agent that should not touch code only adds its scope to `SCOPES`; `scope-guard.test.mjs` checks the wiring. The drift step warns and does not fail, so it never blocks auto-merge. Bash can still write files: the guard covers edits, the lanes and tests cover the rest.
