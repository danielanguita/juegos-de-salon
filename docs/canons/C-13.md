## C-13 · Documentation

With each game or relevant change, update:

- `docs/games/<carpeta>.md`: the spec, with these sections in this order: Resumen,
  Reglas, Modos, Flujo, Protocolo de mensajes, Archivos and Excepciones a los cánones (D-213). Whatever
  a game needs beyond that goes in a section of its own. Every game gets its own page (C-21), named after its code folder: `docs/games/queens.md` for the one in `cup/games/queens/`. `games.test.mjs` checks every game's page against the template; what an older one still lacks is debt in `docs/games-debt.json`.
- `docs/REQUERIMIENTOS.md`: requirements with their own prefix and status.
- `docs/decisions/D-<n>.md`: one numbered decision (D-n) per non-obvious choice, with its why and its consequences; `docs/DECISIONS.md` is its generated index (D-394).
- `README.md`: the game's section with screenshots, **in English** (see below).
- `CHANGELOG.md`: what changed, in which version.

**Everything internal is in English** (D-316, which amends D-78): documents, decisions, specs,
changelog entries, code comments and identifiers, file names, tool messages, commits, PRs and
GitHub issues. Only what the player reads stays in the app's languages (C-3), and persisted data
keys keep their names. The README is the first door for people from anywhere: what it shows
generated is English too (modes from the `en` of each `rules.js`, themes from the `en` of the decks,
captions in `docs/capturas.json`). Spanish text and names still in the repo are migrated in phases
(D-316); new text is English even inside a file that is still Spanish.

The README is not kept by hand: `python3 tools/release/readme.py` maintains it.

- What can be derived from the code —the games table, modes, themes with their card count, names
  per language, tests, document index and screenshot galleries— lives between
  `<!-- generated: ... -->` markers and `update` rewrites it from `tools/release/facts.mjs`, which imports
  the real modules. Inside those markers nothing is edited by hand.
- The prose is written by a person. `check` compares today's facts against the last seal
  (`docs/facts.json`) and names what changed and which section must be reread; `seal` records it
  once it has been reread. A material change that did not go through there does not get published:
  the `tests` check runs `readme.py check` on each PR and before publishing (C-11, D-205).
- Screenshots come from the `tools/e2e/` scripts: `docs/capturas.json` says which script and
  which shot each image comes from, and `capturas <seccion>` remakes them. A new screen in the
  README is a new shot in the script, not a hand crop. They are looked at before publishing
  (C-12) and saved at twice the width they are shown at.
- An outdated screenshot is a warning in any PR, not a blocker. Only "actualiza el README"
  requires bringing them all up to date (D-213).

Whatever still falls behind is picked up by the `documentation` agent (D-172): a round over what
reached `main`, launched by the processes agent on days something came in (D-276), and a review of each PR before proposing its merge, with
`node tools/agents/document.mjs check` and its memory in `docs/documentation.json`. It does not replace this
rule: whoever changes something documents it in the same PR.
